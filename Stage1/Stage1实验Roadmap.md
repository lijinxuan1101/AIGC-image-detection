# Stage 1 实验 Roadmap

> 创建日期：2026-10-26  
> 状态：待开始；本文件是执行路线，不代表已下载数据或运行模型。  
> 设计依据：[[AIGC图像检测论文设计]]、[[RRDataset实验设计]]。

## 阶段目标

用固定官方检测器诊断：**整图生成图片在真实社交传播后，失效来自排序能力受损、阈值漂移，还是二者并存？** 同时检查真实照片误报与生成图片漏检。

本阶段不训练新模型、不采用双塔、不预设创新点。完成条件是得到可靠的诊断证据和下一阶段的选择依据，未发现明显差距也属于有效结果。

## 执行总览

| 顺序 | 工作 | 交付物 | 进入下一步的条件 |
|---|---|---|---|
| M0 | 确认运行环境与存储 | 环境和资源记录 | 确认数据与三个模型可运行的方案 |
| M1 | 核验 RRDataset | 数据结构与配对审计 | 标签和可分析粒度明确 |
| M2 | 划分数据并冻结协议 | 样本清单、划分与阈值规则 | 无源图跨集泄漏 |
| M3 | 跑通三个基线 | 权重记录、冒烟测试分数 | 输入、分数方向及失败处理正确 |
| M4 | 原图／传播图推理 | 逐图连续分数 | 预测记录完整可追溯 |
| M5 | 传播失效诊断 | 指标、图表与案例 | 排序、运行点和两类错误分别分析 |
| M6（有条件） | 模拟与真实传播对比 | 同源三版本分析 | 有可靠原图映射，且确有必要 |
| M7 | 阶段结论与决策 | Stage 1 报告 | 明确后续路线或停止该方向的理由 |

按依赖顺序推进，不预设完成日期。下载解压空间和 GPU 可用性确认后再估算工期。

## M0：环境与资源

- [ ] 确认实验运行位置、GPU 型号与显存、Python／CUDA 环境。
- [ ] 确认下载和解压存储；发布包压缩大小合计约 22.28 GB，解压大小尚未确认，额外预留权重、缓存和结果空间。
- [ ] 分离原始数据、权重、代码和结果目录；Obsidian 中只放笔记与结果索引，不放大规模图片及权重。
- [ ] 固定依赖和版本记录，必要时为不同基线分别建立环境。

**产出**：环境、存储位置与运行配置记录。尚不下载或采集额外平台数据。

## M1：下载与数据审计

入口：[RRDataset 发布页](https://zenodo.org/records/14963880)。

- [ ] 核对文件清单、校验值与发布说明，再下载所需数据。
- [ ] 检查目录、说明文件、真假标签和生成器／场景标识。
- [ ] 核验原图与传播图的共同 ID 或映射，抽样人工确认。
- [ ] 检查是否提供平台、传输顺序、轮次及中间版本。
- [ ] 检查原图训练／验证包和测试包之间的源图、派生图与近重复。
- [ ] 排除扫描、屏幕翻拍等重新数字化数据，以及不符合整图任务范围的样本。

**产出**：目录摘要、各条件样本计数、字段缺失表、配对覆盖率与已知重合记录。

**决策门槛**：

- 配对可靠：开展同图分数与判决变化分析。
- 无配对：仅做各子集总体评测，并说明组成混杂，不能解释为同图传播效应；先排查映射能否恢复。
- 无平台标签：不做跨平台归因；无中间版本：不做逐轮归因。

## M2：样本选择与协议冻结

- [ ] 先建立探索集，初始目标为约 400 张原图：200 real、200 fake，覆盖多个开发生成器和场景；依据数据审计调整。
- [ ] 同一源图的全部版本放入同一划分，近重复也按组处理。
- [ ] 另设独立源域校准集；明确它的来源、是否包含传播增强及样本量。
- [ ] 封闭最终评测集，探索集上的分析不能称作最终独立测试。
- [ ] 最新 1–2 个生成器继续留出，不用于本轮选择方法与调参。
- [ ] 固定清单、随机种子、纳入／排除标准以及原图与传播图的比较规则。

**产出**：带 source_id 的样本 manifest、划分文件、协议配置及版本号。

400 张指源图数量，不把派生版本当独立源图；这一级规模主要用于流程和明显失效诊断，不足以支撑极低误报结论。

## M3：官方基线与小样本验证

| 基线 | 作用 | 官方入口 |
|---|---|---|
| CLIP 2024 | 预训练视觉表征参照 | [代码](https://github.com/grip-unina/ClipBased-SyntheticImageDetection) |
| B-Free | 数据去偏方法参照 | [代码](https://github.com/grip-unina/B-Free) |
| NPR | 邻近像素取证对照 | [代码](https://github.com/chuangchuangtan/NPR-DeepfakeDetection) |

每个模型依次完成：

- [ ] 核验官方 checkpoint 的训练来源、下载地址、文件哈希与代码 commit。
- [ ] 记录基础模型预训练来源和无法核实的样本重合。
- [ ] 保留官方预处理、多裁剪及分数聚合，记录尺寸不足和异常图片的处理方式。
- [ ] 在少量有效 real／fake 原图及传播版上测试，核对输出、分数方向与重复运行一致性。
- [ ] 统一记录 fake=1、分数越高越倾向 fake；不强行把任意分数解释为概率。
- [ ] 保存模型加载和推理失败日志，不静默丢弃样本。

**产出**：基线权重登记表、环境记录与小样本预测文件。

不微调 RRDataset；不使用 RRBench 作者重新训练后的权重混充原始官方权重。若基线原图已接近随机，先检查实现与来源，再限制对其传播下降的解释。

## M4：批量推理与阈值设置

```text
源图版本清单
    ↓ 每个版本独立输入
官方预处理 → 固定检测器 → 连续分数
    ↓
默认阈值 / 独立源域验证阈值
    ↓
逐图结果 → 原图与传播图比较
```

- [ ] 三个模型独立推理，不融合；传播版检测不额外输入原图。
- [ ] 原图与传播图使用相同 checkpoint 和相同模型预处理规则。
- [ ] 官方默认阈值和源域锁定阈值分别报告；不在传播测试数据上选阈值。
- [ ] 核对预测条数、缺失与重复，保存运行配置、日志和耗时。

**每条记录至少包含**：source_id、variant_id、split、label、condition、generator、scenario、可用平台信息、model、checkpoint、raw_score、threshold_id、prediction。缺失信息写 unknown。

**产出**：每模型预测文件与完整性检查记录，可据此重算指标，不必反复推理。

## M5：诊断图表与指标

- [ ] 比较原图与传播图 AUROC、AP，报告类别比例与样本量。
- [ ] 在固定阈值下报告 FPR、TPR、Balanced Accuracy，区分真实图误报和生成图漏检。
- [ ] 绘制 ROC 及低 FPR 区域，不能仅凭总体 AUROC 判断运行点保持。
- [ ] 分别绘制真假两类的分数分布，分析位移、展宽与重叠。
- [ ] 配对有效时计算同图分数差与 real→fake、fake→real 翻转率。
- [ ] 元数据允许时，按生成器、场景或平台分组，报告最差子组而非仅总体均值。
- [ ] 置信区间按 source_id 分组重采样，传播版本不视为独立样本。
- [ ] 检查代表性错误案例，区分输入异常、数据偏差与可能的模型失效。

**产出**：指标表、分数分布、ROC、配对变化图及错误案例清单。

目标域阈值修复实验是可选诊断：在单独目标开发子集选阈值，在独立目标子集评测，单列目标域访问条件；不得作为无目标域方案成绩。

## M6：模拟到真实对比（有条件开展）

仅在原图映射可靠、且 M5 显示值得追查时开展。

- [ ] 同一原图构造固定参数或固定种子的模拟版本，记录处理类型、顺序与参数。
- [ ] 比较原图、模拟版、真实传播版，保持模型、源图与阈值不变。
- [ ] 控制图像尺寸等可观测因素，检查通用模拟是否低估真实传播影响。
- [ ] 区分“发现差距”与“解释差距”；不能仅凭尺寸或质量相近就认为处理相同。
- [ ] 不用封闭测试结果反向选择模拟参数。

**产出**：模拟配置、配对三版本结果及差距是否稳定的判断。暂不实施大规模平台上传；只有确有缺失信息时，再设计补采。

## M7：Stage 1 报告与下一阶段

| 结果 | 后续决策 |
|---|---|
| 排序与低 FPR 可分性保持，但固定阈值失效 | 优先研究源域运行点选择及分数迁移 |
| 排序下降，阈值调整改善有限 | 转向传播训练与表征适配 |
| 模拟表现好、真实传播失效 | 研究模拟偏差与跨条件迁移 |
| 问题集中在场景或来源 | 先控制数据偏差，复核失效是否成立 |
| 无稳定差距或主要基线已足够稳健 | 不强行以传播差距作为论文主线 |

报告应包含：数据审计、权重与训练来源、明确协议、结果及不确定性、可复现案例、局限和下一步选择。区分观测事实与机制推测。

### 完成检查

- [ ] 数据与权重来源可追溯，未知项明确。
- [ ] 三个基线已运行，或记录无法运行的原因及其影响。
- [ ] 排序、固定阈值错误率和两类错误均有结果。
- [ ] 仅在映射可靠的样本上做配对分析，缺失覆盖率有记录。
- [ ] 探索数据与封闭测试分离，无目标域调参混报。
- [ ] 给出是否进入 Stage 2、选择哪条方向的证据。

需要注意：

- Stage 1 是诊断，不是 RRBench 微调成绩的直接复现，也不自动构成方法创新。
- RRDataset 不能替代最新生成器留出测试，数据包含某生成器不等于某基线训练时没见过它。
- 文件夹中的勾选项由实际进度更新；当前任务只创建路线文档，不代表已执行下载、推理或平台上传。
